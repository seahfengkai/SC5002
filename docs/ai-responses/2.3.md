- **Exact prompt (student message):**

> Why does setting the Ridge penalty alpha extremely high (e.g., 1000) cause model performance (R² score) to drop significantly?

## Response (verbatim)

A very large alpha makes the model **underfit**. The penalty gets so strong that the model stops learning the real relationship in the data.

**What alpha does**

Ridge regression minimizes:

  Loss = Σ(yᵢ − ŷᵢ)² + α · Σ βⱼ²

The first term rewards fitting the data. The second term penalizes large coefficients, and alpha sets how much that penalty counts compared with fitting the data.

- **Small alpha:** close to ordinary least squares. The model fits the data closely, and on noisy or highly correlated features it may overfit.
- **Moderate alpha:** the coefficients shrink somewhat. You accept a little bias in exchange for lower variance, and test performance often improves.
- **Very large alpha (e.g., 1000):** the penalty dominates the loss. The cheapest way to minimize it is to push every coefficient close to zero.

**Why R² drops**

When all the β's are near zero, the prediction becomes ŷ ≈ intercept, which is roughly the mean of y. The intercept isn't penalized, so it survives. A model that always predicts the mean has an R² of about **0** by definition. So the score falls toward 0, and it does so on both the training and the test set. Seeing both scores low tells you the problem is underfitting, not overfitting.

In bias-variance terms, raising alpha lowers variance but raises bias. Past some point the added bias costs far more than the variance you save, so the error goes up.

**Why 1000 specifically can be "too high"**

Alpha has no fixed scale. Its effect depends on:

1. **Feature scaling.** If your features weren't standardized, the penalty hits them unevenly. Features with small numeric ranges need large coefficients, so they get shrunk far more heavily. Always use `StandardScaler` (for example, in a `Pipeline`) before Ridge.
2. **Number of samples.** In scikit-learn, the squared-error term is a sum over samples and isn't divided by n. So the same alpha is relatively stronger on a small dataset and weaker on a large one. Alpha = 1000 might barely matter with 1,000,000 rows and wipe out the model with 200 rows.
3. **Signal strength.** If the true coefficients are small or the signal is weak, a moderate penalty can already cancel them out.

**How to fix it**

Don't choose alpha by hand. Search over a log-spaced range with cross-validation:

```python
from sklearn.linear_model import RidgeCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
import numpy as np

model = make_pipeline(
    StandardScaler(),
    RidgeCV(alphas=np.logspace(-3, 3, 50))
)
model.fit(X_train, y_train)
print(model[-1].alpha_)
```

If you plot validation R² against alpha on a log scale, you'll usually see a curve that rises and then falls. On the left, a small alpha may overfit. On the right, a large alpha underfits, and that's where R² collapses toward 0. The best alpha is near the peak.

**In short:** at alpha = 1000 the penalty on coefficient size outweighs the goal of fitting the data. Ridge shrinks all the coefficients toward zero, the model ends up predicting roughly the mean, and R² drops toward 0.
